Зачем мы это делаем

Hello Static Debug — учебный проект команды из пяти студентов. Мы учимся веб-разработке на практике: не по слайдам, а создавая настоящий сайт, который живёт в GitHub-репозитории и автоматически деплоится на GitHub Pages. Здесь мы отрабатываем всё, что даёт преподаватель: семантическую вёрстку, работу с ветками Git, код-ревью, линтеры и командное взаимодействие.

Сайт начинался как «погода по городам», но мы сознательно ушли от этой идеи: внешние API стабильно блокировались в учебных сетях и предпросмотре редактора, и половина команды видела вместо прогноза ошибку. Поэтому теперь сайт полностью автономный — весь контент и все четыре мини-игры работают прямо из файлов, без интернета.

Почему всё работает офлайн

  • 🔌Ноль запросов к API. Все данные (цитаты, факты, вопросы викторины) лежат прямо в JS-файлах.
  • 🖱️Двойной клик — и готово. index.html открывается из проводника без сервера и сборки.
  • 🪶Легче одной фотографии. Каждая страница весит меньше 100 КБ вместе со стилями и скриптами.
  • 🛡️Нечему ломаться. Нет зависимостей от чужих серверов — значит, нет ошибок «не удалось загрузить данные».

Как мы работаем

  1. 1 Идея попадает в Issues на GitHub: что сделать, зачем и кто берёт задачу.
  2. 2 Каждый работает в своей ветке — правки в main напрямую не льём никогда.
  3. 3 Готовая работа — это Pull Request: минимум один ревью от тимлида, линтеры должны быть зелёными.
  4. 4 После вливания в main GitHub Actions автоматически деплоит сайт на GitHub Pages.

Технологии

  • 🧱HTML5 — семантические теги: header, nav, main, section, details.
  • 🎨CSS3 — переменные, Flexbox, Grid, тёмная тема через data-атрибут.
  • ⚙️JavaScript ES2022 — DOM, события, localStorage; без фреймворков и библиотек.
  • 🚀GitHub Pages + Actions — пуш в main = сайт обновился сам.
  • 🧹ESLint, Stylelint, html-validate — три линтера следят за чистотой кода.
